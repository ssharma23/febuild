# Lending Intelligence: "Speed AND Trust" for MeridianLink's credit unions

An end-to-end Databricks build, from file ingestion to an underwriter app. Credit unions decide most consumer loans in minutes **and** catch income misstatement before booking. A pilot-vs-control experiment proves the impact.

> **All data is 100% synthetic**, generated by `src/notebooks/00_generate_dataconnect_extracts.py` and modeled on the shape of MeridianLink Data Connect extracts. It contains no customer data, real people, employers or accounts.

## Outcome (difference-in-differences, 2 pilot vs 2 control credit unions)
- **Auto-decisions:** 31% → 58%.
- **Median time to decision:** 17 h → 8 min.
- **Pull-through:** +5.5 pts, net of control.
- **Early payment default:** −1.2 pts, net of control.
- **Value:** ≈ **$3.6M a year per 40K-application credit union**.
  - $1.71M avoided early-default losses.
  - $0.85M from extra funded loans.
  - $0.72M of underwriter capacity.
  - $0.35M from declines turned into funded loans.
  - Every dollar is reproducible from `ml_lend_semantic.v_value_bridge` × `ml_lend_gold.roi_assumptions`.

## Architecture
```
MeridianLink Data Connect files ─► UC Volume ─► Lakeflow (Auto Loader) ─► BRONZE ─► SILVER ─────────────► GOLD star schema
   (applications, members CDC,                    streaming tables      expectations + quarantine     fact_application, fact_loan_performance,
    payments, notes, pay-stub PDFs)                                     AUTO CDC SCD1/SCD2            dims, outcome KPIs
                                                                        ai_parse_document/ai_extract
                                                                        ai_classify (notes)
GOLD ─► ML: LightGBM EPD model (MLflow, UC registry @champion, SHAP reason codes) ─► Model Serving `ml-lend-epd-risk`
GOLD ─► Semantic: metric views mv_loan_funnel · mv_decision_speed · mv_portfolio_risk ─► Genie · AI/BI dashboard · Databricks One
GOLD/ML ─► underwriting_queue ─► Lakebase synced table ─► Databricks App "Lending Intelligence Workbench"
                                                           live: ai_parse_document → ai_extract → Model Serving → route
                                                           decisions + ai_query letters ─► Lakebase ─► Delta (ml_lend_ops)
Unity Catalog everywhere: Data Classification → class.* tags → ABAC masks; tenant_isolation_key → ABAC row filter; RBAC per layer
```

## Requirement → implementation
| Requirement | Implementation |
|---|---|
| Lakeflow ingest | `read_files` / Auto Loader streaming tables over the Data Connect volume (`01_bronze.sql`) |
| Medallion | bronze → silver → gold in one serverless pipeline |
| Data quality | Expectations (`FAIL UPDATE`, `DROP ROW`, warn) + quarantine tables; results in the event log + dashboard |
| Data classification | UC Data Classification with auto-tagging (`class.us_ssn`, `class.email_address`, …) |
| ABAC | Tag-matched column masks (SSN, DOB, contact) + `tenant_isolation_key` row filter (`sql/20_governance.sql`) |
| RBAC | Schema-level grants per layer (`sql/21_rbac.sql`, `sql/30_app_grants.sql`) |
| AI Functions | `ai_parse_document`, `ai_extract`, `ai_classify` (pipeline), `ai_query` (letters, app) |
| ML model | EPD LightGBM, time-based validation, UC registry, Model Serving |
| Genie + AI/BI | Genie space on metric views; 3-page dashboard |
| Genie Ontology | 3 metric views + 2 domain pages (`docs/ONTOLOGY_DOMAIN.md`). Domain object creation was blocked only by the sandbox's tag-policy quota |
| Databricks One | Dashboard + Genie consumed via Databricks One |
| App + Lakebase | Workbench app; Lakebase Autoscaling project, synced table, write-back, Lakebase → Delta |

## Known limitations (honest notes)
- **No account-level groups.** The FEVM sandbox has none, so personas map through `ml_lend_gov.tenant_entitlements`. Production would use IdP-synced groups with the same policies.
- **Lakebase CDF config (Beta)** is created but hadn't materialized during testing. `07_sync_workbench_to_delta.py` (a job) is the reliable return path.
- **Genie Ontology domain object** is not created because of the account tag-policy cap. The content and metric views exist.
